# MVP の設計

要件定義の「8. 最小限の完成条件（MVP）」を満たすための設計です。実機での検証の結果（[research.md](research.md)）を前提にしています。

## 流れ

1. エージェントが HTML の資料を登録する（MCP のツールか CLI）。
2. 人が Kindle Scribe のブラウザで一覧を開き、資料を読んで、ペンで書き込む。書き込みは端末に保存され、つながっていればすぐサーバーに送られる。
3. 人が「送る」を押す。その時点の書き込みが「フィードバック」としてサーバーに記録される。
4. 人がエージェントのセッションで「読んで」と指示する（またはコマンドを実行する）。エージェントはフィードバックを取得し、元の資料と手書きを理解する。
5. エージェントは、ふだんはセッションの会話で応答する。人が頼んだときは、回答や改訂版を元のフィードバックへの返信として登録し、Kindle の一覧に出す。どちらの場合も、フィードバックは「処理済み」になる。

サーバーがエージェントを起動することはありません。エージェントが取りに行きます。

## 構成

| 部分 | 内容 |
| --- | --- |
| サーバー（`src/server.mjs`） | 依存なしの Node.js。資料・書き込み・フィードバックをファイルに保存する。HTTP と、証明書を渡せば HTTPS でも待ち受ける。認証なし、LAN 専用 |
| Kindle 向けのページ（`public/`） | 一覧と、閲覧兼書き込みの画面。ES5 で書く |
| CLI と MCP サーバー（`bin/scribe-loop.mjs`） | サーバーの HTTP API を呼ぶ。MCP は stdio |
| 合成画像（`src/render.mjs`） | 資料と手書きを重ねた PNG を作る。任意。`playwright-core` と Chrome があるときだけ |

## 資料の表示

- 資料の HTML は、スクリプトを動かさない iframe（`sandbox="allow-same-origin"`）で表示する。サーバーは CSP でスクリプトと外部の読み込みを止める。
- 既定のスタイル（白黒、大きめの文字、右に広い余白）を差し込む。資料側の CSS で上書きできる。
- 資料の後ろに白紙を 1 ページ足し、自由に書けるようにする。
- 画面はページ送り。スクロールより書き換えが少なく、検証でも同じ評価だった。

## 書き込み

- ペン・指・手のひらは区別できないので、どれも線になる。書いている最中に別の接触が来たら無視する。
- Canvas で描き、`getCoalescedEvents` で点を取りこぼさない。
- 書き込みは ID 付きの操作（追加・削除）として、まず localStorage に保存し、サーバーに冪等に送る。
- 線を書き終えるたびに、その下にある文字（`caretRangeFromPoint`）とブロック要素（`elementFromPoint`）を端末側で記録する。サーバー側で組み直すとフォントや幅の違いで位置がずれるため。下線のような平たい線では、少し上の文字を拾う。

## フィードバック

- 「送る」を押すと、端末は未送信の操作を送り切ってから、フィードバックを作るよう頼む。オフラインのときは、つながってから送る。
- フィードバックには、その時点のすべての線と、前回のフィードバックから増えた線の ID を記録する。
- 状態は `pending`（未処理）→ `processing`（処理中）→ `done`（処理済み）。エージェントが変える。
- 返信の資料は、元のフィードバックと元の資料に紐付く。

## 書き換え

- 資料は版を持つ。エージェントが書き換えると版が一つ進み、前の版の資料と書き込みは残る（`source.r<n>.html`、`ink.r<n>.jsonl`）。新しい版は書き込みなしで始まる。本文の位置が変わるので、前の版の線を引き継ぐとずれるため。
- 書き換えは、セッションで人が頼むか、資料の「☐ 書き換え」にチェックを入れて送ると行う。チェックを入れて送ったフィードバックは、希望が「書き換え」になる。
- 書き込みの操作には版を書いておく。書き換えのあとに届いた古い版の操作は、古い版の書き込みに入る。
- Kindle は資料を開いているあいだ、版が進んだかを確かめ、「新しい版」ボタンを出す。書いている最中に画面が変わらないよう、自動では切り替えない。

## エージェントに渡すもの

- 資料の題名と HTML
- 線ごとの、書かれた位置と、その下の文字・要素
- 手書きの線だけの SVG
- 資料と手書きを重ねたページごとの PNG（作れるとき）

手書きの文字の読み取りや、線の意味（下線、丸囲み、取り消し、矢印）の解釈はエージェントに任せます。
