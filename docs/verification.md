# 実機での検証の手順

要件定義の「7. 最初に検証すべき事項」を、Kindle Scribe の実機で確かめる手順です。全体で30分ほどかかります。

書いた線と操作の記録は、自動でサーバーに送られます（`prototype/` を参照）。結果を書き写す必要はありません。

## 準備

1. サーバーで `prototype/server.mjs` を、LAN 側の IP で待ち受けるように起動する（README を参照）。
2. Kindle Scribe のブラウザで `http://<サーバーの IP>:8470/` を開き、ブックマークする。

開けない場合は、そのときの画面の表示を控えておきます。

## 手順

0. **入力を調べる**
   - 「ペン・指・手のひらの見分け」で、各枠を書いてあるとおりになぞる。
   - 初代 Scribe（Silk、Chrome 80 相当）はペンも `pointerType: "touch"` で渡すので、ペンと指を見分けられる値（`width`/`height`、`pressure`、`buttons`）があるかをここで調べる。
1. **環境を確かめる**
   - 一覧ページの下に、この端末で使える機能の表が出る。
   - 「サーバーに接続しています」と出ていれば、記録も届いている。
2. **白紙に書く**
   - 「白紙（Canvas）」と「白紙（SVG）」の両方で、次を書く。
     - 速い線
     - ゆっくりした線
     - 日本語の小さい字
     - 英語
     - 図
   - 「次」でページを移り、前のページに戻って線が残っているかを見る。
   - HTTPS（`https://<サーバーの IP>:8471/`）で開き、「白紙（Canvas + pointerrawupdate）」でも書いて、遅延を比べる。ツールバーに「canvas+raw」と出ていれば `pointerrawupdate` が使えている。
3. **手のひらと消しゴムを試す**
   - 手のひらを画面に置いたまま書く。
   - ペンの反対側（消しゴム端）でこする。
   - 「消しゴム」ボタンで消す。
   - 筆圧を変えて書き、線の太さが変わるかを見る。
4. **文章の上に書く**
   - 「文章・スクロール」と「文章・ページ送り」の両方で、文章中の指示に沿って書き込む。
   - スクロールは「手」を選んでからなぞる（ペンと指を見分けられないので、いまは指でもペンでも線になる）。
   - 残像や、読み書きの切り替えのしやすさを比べる。
5. **中断と再開を試す**
   - 書いたあと、端末をスリープさせて数分後に戻す。
   - 機内モード（Wi-Fi オフ）で書いてから、オンに戻す。
   - タブを閉じて開き直す。
   - それぞれのあと、線が残っているか、ツールバーの表示が「送信済み」になるかを見る。
6. **評価する**
   - 「5 段階の評価」のページで、各項目のボタンを押す。
   - 感想があれば「感想を手書きで」に書く。

## 記録から分かること

| 確かめたいこと | 記録 |
| --- | --- |
| LAN 内のサーバーに届くか | `features`（UA、各 API が使えるか） |
| 連続した手書きができるか | `stroke`（点の数、サンプリング頻度、coalesced の有無） |
| 描画の遅延 | 評価と `stroke` の `lagAvgMs`（イベントが作られてから処理されるまでの遅れ。画面に出るまでの遅れではない） |
| パームリジェクション・筆圧・消しゴム | `stroke` の `pointerType`・`pressures`・`buttons`、`palm`、`touchstart`、`erase` |
| 画面更新と残像 | 評価（スクロールとページ送り） |
| スリープや通信切断からの復帰 | `hidden`/`visible`、`timer-gap`、`offline`/`online`、`ops-send-failed`/`ops-sent`、`restore` |

画面に線が出るまでの遅れは、JavaScript からは測れません。測るときは、スマホのスロー動画（240fps など）でペン先と線を一緒に撮ります。
