# 手書きによるAIエージェントとの対話環境の構築

## 1. 背景・目的

近年、AIエージェントがHTMLやArtifactなどを生成し、人間の理解や意思決定を支援するケースが増えている。

しかし、文章を深く理解する、疑問を整理する、考えを発展させるといった知的活動には、紙に印刷して手書きで書き込むというインターフェースのほうが適していると感じている。

そこで、手持ちのKindle Scribeを活用し、AIエージェントの出力を電子ペーパー上で読み、手書きでフィードバックを返せる環境を構築したい。

単なる電子ノートや手書きOCRではなく、**紙に近い読書・思考体験を維持しながら、AIエージェントとの双方向のコミュニケーションを成立させること**が目的である。

## 2. 実現したいユーザー体験

1. AIエージェントに調査、分析、提案、資料作成などを依頼する。
2. AIエージェントの生成した資料が、自動的にKindle Scribeから閲覧可能になる。
3. Kindle Scribeを手に取り、資料を読む。
4. 紙の資料と同じように、文章や図表の上に直接手書きで書き込む。
5. 読み終わったら、簡単な操作でAIエージェントにフィードバックを返す。
6. AIエージェントが手書きの内容と元の資料を理解し、質問への回答、追加調査、資料の修正などを行う。
7. 新しい資料がKindle Scribeから閲覧可能になる。

このサイクルを繰り返し、AIと人間が共同で思考を深められるようにする。

人間側は、可能な限りKindle Scribeとペンだけで一連の操作を完結できることが望ましい。

## 3. 重視するUX

本プロジェクトでは、機能の多さよりも利用時の摩擦の少なさを重視する。

- 紙に書くような自然な読み書きの体験。
- 資料を読み始めるまでの操作が少ないこと。
- 読むことと書くことをシームレスに切り替えられること。
- 手書き時の遅延が思考を妨げないこと。
- 資料への書き込みに十分な余白があること。
- フィードバックの送信が簡単であること。
- ファイルのダウンロード、アップロード、メール送信、アプリ間の移動などを日常的に要求しないこと。
- AIの応答を待つ間、端末を操作し続ける必要がないこと。
- 中断・再開が容易で、自分のペースで思考できること。

特に、PDFをSend to Kindleで送信し、書き込み後にメールで送り返す方式は、操作上の負担が大きいため、メインの利用方式としては採用したくない。

## 4. 機能要求

### 4.1. AIエージェントからの資料提供

- AIエージェントが生成した資料をプログラムから登録できる。
- 登録された資料をKindle Scribeで閲覧できる。
- 複数の資料を管理できる。
- 新着資料や未読資料を容易に確認できる。
- 文章だけでなく、表、グラフ、図、数式、コードなどを含む資料を扱える。
- 手書きでの思考や回答を前提とした資料を生成できる。

### 4.2. 手書き入力

- 表示されている資料の任意の位置に直接書き込める。
- 日本語・英語などの手書き文字を扱える。
- 下線、丸囲み、取り消し線、矢印、図などを自由に描ける。
- 資料への注釈だけでなく、自由記述や白紙への描画もできる。
- 書き込んだ内容を修正・消去できる。
- ページ移動や端末のスリープによって書き込みが失われない。
- 書き込み内容は可能な限り自動保存される。

### 4.3. AIエージェントへのフィードバック

- 簡単な操作で手書き内容をAIエージェントに渡せる。
- AIエージェントは元の資料と手書き内容の両方を取得できる。
- 手書きの文字だけでなく、書き込みの位置や対象となる文章・図表との関係を理解するための情報を取得できる。
- 手書きの質問、修正指示、回答、図などを区別せずに扱える。
- 人間が手書き内容をテキストに転記する必要がない。

### 4.4. 継続的な対話

- AIエージェントがフィードバックを受けて、新しい資料を提供できる。
- 元の資料、手書きフィードバック、それに対する回答や改訂版の関係を維持できる。
- 過去の資料やフィードバックを参照できる。
- フィードバックの送信状況や処理状況を確認できる。
- AIエージェントが即時に応答しなくても利用できる。

### 4.5. 外部エージェントとの連携

- 特定のAIサービスやモデルに強く依存しないことが望ましい。
- Codex、Claude Code、自作エージェントなどから利用できることが望ましい。
- エージェント側から資料の登録、フィードバックの取得、応答資料の登録などを自動化できる。

## 5. 動作環境・制約

- クライアント端末は手持ちのKindle Scribeを第一対象とする。
- 自宅LAN内にLinuxサーバーを用意できる。
- Kindle Scribeからローカルサーバーに直接アクセスする方式を優先的に検討する。
- 可能であれば、Kindle Scribeの標準機能のみで利用できることが望ましい。
- Jailbreakは必須とせず、標準機能で十分なUXを実現できない場合の選択肢とする。
- 資料や手書きデータの管理について、外部クラウドサービスへの依存を可能な限り減らしたい。
- AIエージェント自体が外部サービスを利用することは許容する。
- 日本語の資料と手書きを問題なく扱えること。
- 将来的には、Kindle Scribe以外の電子ペーパー端末やタブレットにも展開できることが望ましい。

## 6. 想定ユースケース

| 用途 | AIの出力 | 人間のフィードバック |
|---|---|---|
| 技術設計 | 設計案、構成図 | 指摘、構成図の修正 |
| 技術調査 | 調査結果、論文の要約 | 疑問、追加調査の指示 |
| データ分析 | グラフ、分析結果 | 着目点、仮説、追加分析の指示 |
| コードレビュー | コード、差分、設計の説明 | 赤入れ、改善案 |
| 語学学習 | 読み物、作文問題 | 解答、質問 |
| 資格学習 | 練習問題、解説 | 解答、途中計算 |
| アイデア検討 | 論点、選択肢、仮説 | マインドマップ、反論、追加案 |

個別用途に特化したアプリを作るのではなく、AIがその都度適切な資料を生成できる汎用的なインターフェースとしたい。

## 7. 最初に検証すべき事項

本格的な設計・実装に着手する前に、Kindle Scribe上で要求するUXを実現できるかを検証してほしい。

特に以下の実機検証を優先する。

- 標準ブラウザからLAN内のサーバーにアクセスできるか。
- ブラウザ上でペンによる連続した手書き入力が可能か。
- 手書きの描画遅延は実用上許容できるか。
- パームリジェクション、筆圧、消しゴムなどをどの程度利用できるか。
- 電子ペーパー特有の画面更新や残像が使い勝手にどう影響するか。
- スリープや通信切断から自然に復帰できるか。

標準ブラウザでの手書きが実用的でなければ、他の方式を調査・比較する。

本プロジェクトの成否は、AI連携の高度さよりも、日常的に使いたくなる手書き体験を実現できるかどうかに大きく依存する。

## 8. 最小限の完成条件（MVP）

以下の一連の操作が成立することを最初の目標とする。

- [ ] AIエージェントが資料を登録する。
- [ ] Kindle Scribeでその資料を開く。
- [ ] ペンで資料に直接書き込む。
- [ ] 書き込みが保存される。
- [ ] 簡単な操作でフィードバックを送信する。
- [ ] AIエージェントが元の資料と手書き内容を取得・理解する。
- [ ] AIエージェントが回答または改訂版を登録する。
- [ ] Kindle Scribeで新しい資料を読む。

この一連の操作にメールの送受信や手動のファイル転送が不要であること。

## 9. 設計・実装の方針

具体的なアーキテクチャ、プログラミング言語、通信方式、データ形式、画面構成、AIとの連携方式などは指定しない。

既存OSSの活用、改修、組み合わせも含めて検討し、要求を満たすための適切な設計を提案してほしい。

特にKindle Scribeの制約に関しては、一般的なWebブラウザの挙動を前提とせず、実機で検証可能な小規模なプロトタイプから進めることが望ましい。

## 10. 調査済みの参考資料

### Hermes Notebook

https://github.com/lEWFkRAD/hermes-agents-guide-to-the-galaxy

今回の目的に最も近い先行事例。Kindle Scribeの標準ブラウザを利用した手書き入力、AIエージェントとの対話、Live Pagesなどを実装している。最優先で調査する価値がある。

### Ignite

https://github.com/markrai/ignite

Kindle Scribe向けのノートアプリ代替実装。Webアプリと同期サーバーも含む。ネイティブでの手書き処理や同期方式の参考になり得る。

### Grimoire

https://github.com/grimoire-notes/grimoire-scribe

Jailbreak済みKindle Scribe向けの手書きノートアプリ。ネイティブ実装による手書き体験や端末固有の機能を調査する際の参考資料。

### Kindle Scribe MCP

https://github.com/starkshtlm/kindle-scribe-mcp

AIエージェントからKindle Scribeへの資料送信と手書きフィードバックの回収を実現するMCPサーバー。PDFとメールを利用するため、今回求めるUXとは異なるが、AIエージェントとの連携設計の参考になる。

なお、これらのプロジェクトについて、手持ちのKindle Scribeでの動作やコードの詳細までは未検証である。
